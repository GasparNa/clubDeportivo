# Actividad: diseñar tres casos de prueba

En grupos, trabajen sobre el módulo de su proyecto. Cada grupo debe definir tres casos de prueba:

**Caso 1**. Camino feliz.
Una operación con datos válidos que debería completarse correctamente.

**Caso 2**. Caso de error.
Una entrada inválida, un recurso inexistente o una condición que deba provocar un rechazo.

Caso 3. Regla de negocio.
Una condición propia del dominio que el sistema debe respetar.

Para cada caso, definan:
* ID y título.
* Precondiciones.
* Datos de entrada.
* Pasos.
* Resultado esperado.
Carguen los casos en Testiny.

> Criterios de calidad: otra persona debe poder ejecutar el caso sin tener que preguntar qué datos usar, que acciones realizar o que resultado se espera

# Proposal

## Why

This OpenSpec change proposes the design and implementation of a complete API for a **Sports Club Reservation System** using API-First approach. The system manages court reservations, equipment rental, and member management for a Deportivo Club using OpenAPI specifications.

The need arises from the requirement to organize the API into 4 independent modules that allow different team members to work in parallel feature branches without conflicts. The API-First approach ensures contracts are defined before implementation, enabling consistent CI/CD pipelines and clear integration points.

## What Changes

- Creation of 4 main API modules working in parallel feature branches
- OpenAPI specification for all endpoints following REST conventions
- Specifications strictly based on provided SQL schema files
- CI/CD-ready API contracts for consistent deployments

### New Capabilities

- `gestion-usuarios-personas` - User registration, authentication, profile management
- `gestion-instalaciones-horarios` - Court management, disciplines, time slots
- `gestion-reservas-turnos` - Main reservations, equipment rental
- `pagos-auditoria-notificaciones` - Payment tracking, system activities, notifications

### Modified Capabilities

- None (new implementation)

## Impact

- API contracts for 4 independent modules
- Feature branches: `feature/openapi-integrante-1`, `feature/openapi-integrante-2`, etc.
- OpenAPI specifications exportable for code generation
- CI/CD pipelines for API validation and deployment
- Database SQL schemas as source of truth (backend/db/esquemaUltimo.sql, backend/db/persona.sql, backend/db/esquema-final.sql)
- Documentation sources: docs/bbdd.md, docs/modelo-datos.md, Requerimientos - Ing. de Software.docx, Consigna_TP_Reservas_OpenSpec_CICD (1).pdf
